# portolan-ops

This repository is the canonical source for Portolan's organization-wide standards and shared files. CI syncs workflow callers, contributor policies, templates, and brand assets from here.

Here's what you can do with this repo:

## Change a shared file everywhere

To change shared files like our copy, branding, or contributor policy, open a PR against main with your updates. Once merged to `main`, the changes will automatically propagate to all downstream repos (defined in `sync/manifest.yml`) via a pull request. For most repos, those PRs are set to auto-merge.

To preview a change's reach before merging:

```bash
python3 scripts/sync.py --dry-run --plan-only
```

In this repo, two files have content generated by scripts. CI will fail when these have not been rebuilt after editing, so make sure to run this as needed:

```bash
python3 scripts/build_agents_block.py   # after editing AGENTS.md
python3 brand/emit_css.py --write       # after editing brand/brand.json
```

## Change shared CI

Each repo contains a small workflow file that points at the shared one here, pinned at the `v1` tag. GitHub fetches it from this repo on every run. To change shared CI:
1. Edit the workflow in [`.github/workflows/`](.github/workflows/)
2. Confirm `ci-selftest.yml` passes on the pull request
3. Merge

The merge releases itself: `release.yml` tags the commit and moves `v1`, and downstream repos pick up the change on their next CI run. A breaking change needs a person. See [docs/maintaining-ci.md](docs/maintaining-ci.md#releasing-a-ci-change).

## Create a new repo

To initiate a new repo, use the [`setup-repo`](.claude/skills/setup-repo) skill. It applies org standards and registers the repo in the sync manifest. Note that this skill is a WIP; please open PRs to improve it over time.

## Add an existing repo to ops sync

To make an existing repo inherit from ops sync, add its entries to [`sync/manifest.yml`](sync/manifest.yml) and push.

## What lives here

| Directory | What it governs | Who/what it's for |
|---|---|---|
| [norms/prose.md](norms/prose.md) | How Portolan sounds, and the Vale rules that enforce it | Anyone (human or agent, but especially agent) writing anything for the org |
| [AGENTS.md](AGENTS.md) | Agent norms | Auto-synced to all repos |
| [copy/](copy/) | How Portolan is described, canonical URLs, org profile | Website, announcements, docs |
| [brand/](brand/) | Colors, fonts, logos, and the CSS generator | The website |
| [policies/](policies/) | Code of conduct, contributing, AI policy, security | The org `.github` repo, and through it every repo |
| [norms/](norms/) | How repos, docs, and CI are expected to look | Maintainers and agents |
| [ci/](ci/) | Small workflows that call the shared ones, grouped by repo type | Repos, by CI family |
| [templates/](templates/) | Issue and PR templates, new-repo skeleton files | New and existing repos |
| [sync/](sync/) | `manifest.yml`, which maps files to repos, and `protection.yml`, which records the checks each branch requires | The sync and audit workflows |
| [.github/](.github/) | Reusable CI workflows, the sync job, scheduled jobs | Every repo's CI |
| [.claude/hooks/](.claude/hooks/) | `writing_check.py`, which checks issue and PR bodies before they are filed | Auto-synced to all repos |
| [.claude/skills/](.claude/skills/) | `setup-repo` | Whoever creates a new repo |

## Maintaining this repo

There is no Makefile. Every check is a plain script; CI runs the same ones you can run locally:

```bash
uvx prek run --all-files                       # pre-commit hooks
python3 scripts/check_manifest.py              # manifest is well-formed
python3 scripts/build_agents_block.py --check  # generated agents block is current
python3 brand/check.py                         # generated CSS is current
python3 scripts/sync.py --dry-run --plan-only  # sync plan is sane
python3 scripts/check_workflow_triggers.py     # no pull_request branch filters
python3 scripts/check_protection.py            # required checks match the record
scripts/lychee.sh --offline .                  # relative links and anchors resolve
```

[`renovate.yml`](.github/workflows/renovate.yml) runs every hour. It opens pull requests to update dependencies across the org, and they merge when their checks pass. [`renovate/default.json5`](renovate/default.json5) holds the policy.

These jobs run weekly on their own and open a tracking issue while something is off:
- [`sync-drift.yml`](.github/workflows/sync-drift.yml) reports repos whose synced files no longer match this one
- [`protection-audit.yml`](.github/workflows/protection-audit.yml) reports branches whose required checks differ from `sync/protection.yml`
- [`links.yml`](.github/workflows/links.yml) reports external links that no longer work. The repos in the `ci/links.yml` entry of [`sync/manifest.yml`](sync/manifest.yml) run the same check from [`ci/links.yml`](ci/links.yml)
