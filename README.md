# portolan-ops

This is the operations repo for Portolan, the ground truth for all org standards. Shared content (e.g., CI, contributor policies, templates, branding, etc.) lives here and syncs to other repos automatically via CI. Centralizing these standards lets us maintain them once instead of in twelve places, and helps us build quickly and confidently with agents.

Here's what you can do with this repo:

## Change a shared file everywhere

To change shared files like our copy, branding, or contributor policy, open a PR against main with your updates. Once merged to `main`, the changes will automatically propagate to all downstream repos (defined in `sync/manifest.yml`) via a pull request. For most repos, those PRs are set to auto-merge.

To preview a change's reach before merging:

```bash
python3 scripts/sync.py --dry-run --plan-only
```

In this repo, two files have content generated by scripts. CI will fail when these have not been rebuilt after editing, so make sure to run this as needed:

```bash
python3 scripts/build_agents_block.py   # after editing AGENTS.md
python3 brand/emit_css.py --write       # after editing brand/brand.json
```

## Change shared CI

To avoid CI bugs auto-propagating downstream, CI logic is not synced. Each repo holds a small workflow file that points at the shared one here, asking for the version tagged `v1`. GitHub fetches it from this repo on every run, so a merge to `main` changes nothing until the tag moves. In order to make CI updates propagate, you need to:
1. Edit the workflow in [`.github/workflows/`](.github/workflows/)
2. Merge
3. Confirm `ci-selftest.yml` passed
4. Move the tag onto your commit:

```bash
git tag -f v1 <sha>
git push -f origin v1
```

Downstream repos will then pick up the changes on their next CI run.

## Stand up a new repo

To initiate a new repo, use the [`setup-repo`](.claude/skills/setup-repo) skill. It applies org standards and registers the repo in the sync manifest. Note that this skill is a WIP; please open PRs to improve it over time.

## Add an existing repo to ops sync

To make an existing repo inherit from ops sync, add its entries to [`sync/manifest.yml`](sync/manifest.yml) and push.

## Maintaining this repo

There is no Makefile. Every check is a plain script; CI runs the same ones you can run locally:

```bash
uvx prek run --all-files                       # pre-commit hooks
python3 scripts/check_manifest.py              # manifest is well-formed
python3 scripts/build_agents_block.py --check  # generated agents block is current
python3 brand/check.py                         # generated CSS is current
python3 scripts/sync.py --dry-run --plan-only  # sync plan is sane
```

Three jobs run weekly and open pull requests on their own:
- [`bump-tools.yml`](.github/workflows/bump-tools.yml) raises tool versions Dependabot cannot see
- [`auto-update.yml`](.github/workflows/auto-update.yml) bumps pre-commit hook versions
- [`sync-drift.yml`](.github/workflows/sync-drift.yml) reports repos whose synced files no longer match this one
